# 家族姓氏管理系统 PRD 模块清单

## 1. 文档目的

本文档用于沉淀当前家族姓氏管理系统的 PRD 模块边界、模块职责、页面构成、输入输出与验收重点，方便后续继续扩展产品与迭代研发。

适用对象：

- 产品经理
- UI / UX 设计师
- 前后端研发
- 测试与实施人员

## 2. 角色定义

### 管理员 `ADMIN`

拥有能力：

- 登录系统
- 查看全部数据
- 新建/编辑/删除/恢复成员
- 维护父母关系与婚姻关系
- 上传头像与资料
- 使用图谱和称呼计算
- 管理用户账号
- 管理家族称呼别名
- 查看审计日志

### 普通查看用户 `VIEWER`

拥有能力：

- 登录系统
- 查看首页统计
- 查看成员列表与详情
- 查看图谱
- 使用称呼计算

限制：

- 不能新增、编辑、删除成员
- 不能导出
- 不能管理账号与系统设置

## 3. 模块总览

当前建议的产品模块清单如下：

1. 登录与鉴权
2. 首页统计
3. 成员管理
4. 成员详情
5. 婚姻关系管理
6. 图谱关系中心
7. 亲戚称呼计算
8. 家族称呼别名设置
9. 用户与权限管理
10. 审计日志
11. 文件与照片管理
12. Excel 导入导出
13. 数据质量治理
14. 普通成员补充资料申请
15. 家族资料沉淀

其中：

- `1~10` 为当前已落地或已明确规划模块
- `11~15` 为下一阶段建议重点扩展模块

## 4. 模块级清单

## 模块 1：登录与鉴权

### 目标

- 管理系统访问身份
- 区分管理员与普通查看用户

### 页面

- 登录页

### 核心功能

- 用户名密码登录
- 登录态校验
- 获取当前用户信息
- 退出登录

### 输入

- 用户名
- 密码

### 输出

- 登录 token
- 当前用户角色

### 验收要点

- 错误账号密码提示正确
- 登录成功后按角色进入系统
- 未登录访问受保护页面时跳转到登录页

## 模块 2：首页统计

### 目标

- 让用户快速理解当前家族数据规模与维护进展

### 页面

- 首页看板

### 核心功能

- 成员总数
- 男性人数
- 女性人数
- 在世 / 已故人数
- 代际数量
- 婚配数量
- 最近新增成员
- 最近操作日志

### 验收要点

- 统计值准确
- 数据更新后首页可及时刷新

## 模块 3：成员管理

### 目标

- 管理家族成员基础档案

### 页面

- 成员列表页
- 新建成员弹窗
- 编辑成员弹窗

### 核心功能

- 列表查询
- 按姓名 / 籍贯 / 字辈筛选
- 按性别筛选
- 按生命状态筛选
- 新建成员
- 编辑成员
- 删除 / 恢复成员

### 核心字段

- 姓名
- 性别
- 出生日期
- 去世日期
- 生命状态
- 字辈 / 代际
- 排行
- 籍贯
- 父亲
- 母亲
- 备注

### 下一步增强建议

- 姓名重复提醒
- 疑似重复成员提示
- 快速建父母 / 子女 / 配偶

### 验收要点

- 字段录入后可正确保存
- 父母选择支持检索匹配
- 生命状态与去世日期联动正确

## 模块 4：成员详情

### 目标

- 以成员为中心查看完整档案与关联关系

### 页面

- 成员详情页

### 核心功能

- 查看成员基础档案
- 查看父母信息
- 查看子女列表
- 查看兄弟姐妹
- 查看婚姻关系
- 上传头像
- 从详情页进入图谱
- 从详情页继续维护关系

### 下一步增强建议

- 多照片
- 附件资料
- 生平简介
- 重要事件

### 验收要点

- 成员详情完整可读
- 关系数据与图谱一致

## 模块 5：婚姻关系管理

### 目标

- 支持配偶与再婚关系管理

### 页面

- 成员详情页中的婚姻关系区
- 新建 / 编辑婚姻关系弹窗

### 核心功能

- 选择配偶成员
- 婚姻状态维护
- 开始日期
- 结束日期
- 删除 / 恢复婚姻关系

### 下一步增强建议

- 多段婚姻排序
- 婚姻关系历史视图

### 验收要点

- 配偶关系不能重复建立
- 成员不能与自己建立婚姻关系

## 模块 6：图谱关系中心

### 目标

- 可视化展示以某成员为中心的家族关系网络

### 页面

- 图谱页

### 核心功能

- 搜索成员并切换图谱中心
- 点击节点切换中心人物
- 展示父母、配偶、子女、兄弟姐妹
- 支持 2 跳关系展开
- 右侧展示中心人物摘要

### 下一步增强建议

- 图谱筛选：只看血缘 / 包含婚姻 / 只看直系
- 两成员路径高亮
- 图谱中的关系标签优化
- 图谱导出图片

### 验收要点

- 图谱可流畅切换
- 节点和关系含义清晰
- 中心人物摘要与节点一致

## 模块 7：亲戚称呼计算

### 目标

- 提供家族亲属称谓计算能力

### 页面

- 称呼计算页

### 核心功能

- 成员对成员称呼计算
- 路径式称呼计算
- 显示标准称呼
- 显示家族别名称呼
- 显示关系路径
- 支持双向称呼结果

### 下一步增强建议

- 路径高亮跳转图谱
- 复杂关系结果解释
- 方言称呼包

### 验收要点

- 常见亲属关系结果准确
- 路径式输入与成员互算结果逻辑一致

## 模块 8：家族称呼别名设置

### 目标

- 让通用中文亲属称谓映射为家族实际叫法

### 页面

- 系统设置页中的别名映射配置区

### 核心功能

- 关系编码维护
- 标准称呼维护
- 家族叫法维护
- 启用 / 停用

### 验收要点

- 配置后称呼计算结果可正确展示别名

## 模块 9：用户与权限管理

### 目标

- 管理后台账号与角色

### 页面

- 用户权限页

### 核心功能

- 新建账号
- 编辑账号
- 重置密码
- 角色切换
- 状态启用 / 禁用

### 验收要点

- 普通角色不可进入管理页
- 管理员可维护账号

## 模块 10：审计日志

### 目标

- 追踪关键数据变更

### 页面

- 审计日志页

### 核心功能

- 记录登录
- 记录成员新增 / 修改 / 删除 / 恢复
- 记录婚姻关系变更
- 记录头像上传
- 记录权限调整

### 下一步增强建议

- 变更前后字段对比
- 按成员维度查看变更历史

### 验收要点

- 关键操作均有日志
- 时间、操作者、动作、目标可追溯

## 模块 11：文件与照片管理

### 目标

- 管理成员头像及后续资料附件

### 当前状态

- 已支持单张头像上传

### 下一步规划

- 多图上传
- 附件文档上传
- 扫描件归档
- 来源说明

### 验收要点

- 文件不因容器重启丢失
- 文件路径与成员正确关联

## 模块 12：Excel 导入导出

### 目标

- 支持大规模初始录入与数据备份

### 当前状态

- 已支持导出

### 下一步规划

- Excel 批量导入
- 模板下载
- 导入结果报告
- 冲突项提示

### 验收要点

- 大批量成员可导入
- 错误数据可明确反馈

## 模块 13：数据质量治理

### 目标

- 保证谱系数据真实可信

### 下一步规划

- 重名提醒
- 疑似重复成员识别
- 合并成员
- 关系冲突校验
- 日期合理性校验
- 待核实状态

### 验收要点

- 关键错误能够前置发现
- 存疑数据可保留但不会混淆正式数据

## 模块 14：普通成员补充资料申请

### 目标

- 让普通成员也能参与家族资料完善

### 下一步规划

- 提交补充信息
- 管理员审核
- 审批日志
- 资料采纳 / 驳回说明

### 验收要点

- 普通成员可参与补录
- 主数据仍由管理员最终控制

## 模块 15：家族资料沉淀

### 目标

- 把系统从“关系管理工具”升级为“家族记忆资产库”

### 下一步规划

- 生平简介
- 家族故事
- 重要事件
- 家族时间线
- 老照片归档
- 家谱文献资料

### 验收要点

- 单个人节点不再只是结构化关系点，而具备历史信息承载能力

## 5. 跨模块通用规则清单

以下规则建议在 PRD 和研发实现中统一遵守：

### 5.1 数据规则

- 成员不能设置自己为父母
- 父亲与母亲不能指向同一人
- 配偶关系不得重复建立
- 非已故成员默认不应填写去世日期
- 重名成员允许存在，但需支持区分与提醒

### 5.2 权限规则

- 查看用户不可修改成员
- 账号、日志、设置仅管理员可见
- 后续敏感字段建议支持更细粒度权限

### 5.3 交互规则

- 尽量用联想搜索替代手工输入
- 复杂关系展示必须带解释
- 图谱操作后应同步更新摘要区

## 6. PRD 输出建议顺序

建议按以下顺序逐步展开正式 PRD：

1. 成员管理模块 PRD
2. 图谱模块 PRD
3. 称呼计算模块 PRD
4. Excel 导入模块 PRD
5. 数据质量治理模块 PRD
6. 普通成员补录与审核模块 PRD

## 7. 建议优先立项模块

如果当前只继续做 5 个专题，建议优先级如下：

1. 数据质量治理
2. Excel 导入
3. 快速建亲属
4. 图谱路径高亮与关系表达优化
5. 普通成员补录申请
