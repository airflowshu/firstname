# 家族姓氏管理系统产品路线图

## 1. 文档目的

本文档用于明确当前家族姓氏管理系统从原型验证到正式落地的产品推进路线，帮助产品、设计、研发、测试、实施在同一节奏下协作。

当前系统定位：

- 面向单家族谱系的家族血亲关系管理平台
- 以成员档案、父母/配偶关系、图谱展示、称呼计算为核心能力
- 逐步从“后台录入工具”升级为“家族关系知识平台”

## 2. 当前基线版本（已具备）

当前代码基线已具备以下核心能力：

- 登录与角色权限
- 首页统计看板
- 成员管理与详情页
- 父母/配偶关系维护
- 关系图谱展示
- 成员对成员称呼计算
- 路径式称呼计算
- 家族称呼别名映射
- 操作日志
- 本地磁盘头像上传

当前阶段可视为：

- `Baseline / V1.0 原型可运行版`

该版本适合：

- 业务验证
- 原型演示
- 小规模真实族谱试录入

该版本暂未重点解决：

- 大规模录入效率
- 数据冲突治理
- 普通成员协作补录
- 多家族扩展
- 深层隐私治理

## 3. 产品目标分层

### 3.1 近期目标

- 把系统从“能演示”提升为“能真正开始录入真实数据”
- 重点解决录入效率、重名冲突、图谱可读性、称呼解释能力

### 3.2 中期目标

- 把系统从“管理员维护工具”提升为“家族成员协同平台”
- 重点补齐资料补充、审核流、附件资料、时间线能力

### 3.3 长期目标

- 把系统从“单家族系统”提升为“可扩展家谱平台”
- 重点考虑多家族、多权限层级、长期资产沉淀和平台化运营能力

## 4. 分阶段路线图

## 阶段 A：V1.1 可用性强化版

建议周期：

- `2~4 周`

目标：

- 提高数据录入效率
- 减少基础数据错误
- 提升图谱与称呼功能的真实使用体验

重点事项：

1. 成员录入体验优化
- 新建成员时增加关系联想检索
- 在成员详情页支持快速新增父亲、母亲、配偶、子女、兄弟姐妹
- 优化表单联动与字段校验

2. 数据质量治理
- 疑似重复成员提醒
- 关系冲突校验
- 生卒日期合理性校验
- 软删除恢复与异常记录提示

3. 图谱体验优化
- 图谱关系标签优化
- 关系路径可读性提升
- 图谱筛选：只看血缘、包含婚姻、只看直系、代际深度控制
- 图谱中心切换与路径高亮

4. 称呼能力增强
- 两成员之间关系路径展示
- 显示“标准称呼 + 家族叫法”
- 对复杂关系给出解释性结果

5. 数据流转能力
- Excel 导出优化
- 规划 Excel 批量导入模板

阶段验收标准：

- 真实录入 100~300 人时，主要录入流程顺畅
- 重名、关系冲突能被系统及时提醒
- 图谱和称呼计算的结果具备较强可读性

## 阶段 B：V1.2 录入效率与协作版

建议周期：

- `3~5 周`

目标：

- 降低大规模初始建谱成本
- 开始支持家族协同维护资料

重点事项：

1. Excel 批量导入
- 提供导入模板
- 支持导入校验报告
- 支持冲突项、失败项导出

2. 普通成员资料补充
- 普通用户可提交资料补充申请
- 管理员审核后入库
- 保留来源和变更痕迹

3. 资料沉淀
- 单成员多张照片
- 附件资料上传
- 生平简介 / 家族备注 / 重要说明

4. 成员关系辅助维护
- 父母/配偶/子女快捷建人
- 兄弟姐妹自动推导辅助
- 关系缺口补录提示

阶段验收标准：

- 可批量导入家族初始成员数据
- 普通成员可参与补充资料，但不直接破坏主数据
- 管理员维护效率显著提升

## 阶段 C：V2 家族协同与知识沉淀版

建议周期：

- `4~8 周`

目标：

- 让系统从“关系数据库”升级为“家族知识库”

重点事项：

1. 家族资料中心
- 照片墙
- 家族文档
- 族谱扫描件
- 成员事件记录

2. 家族时间线
- 出生、婚配、迁居、去世等事件按时间轴展示
- 可按个人 / 全家族维度查看

3. 关系解释与图谱联动
- 点选两成员，高亮最短路径
- 展示完整关系链条与称呼解释
- 从称呼结果反查图谱路径

4. 审核与版本管理
- 资料补充审批流
- 历史版本查看
- 成员信息变更对比

阶段验收标准：

- 不只是“能查关系”，还可以“沉淀家族记忆”
- 资料补录、关系校验、版本回溯形成闭环

## 阶段 D：V3 平台化预留版

建议周期：

- `按业务需要推进`

目标：

- 为多家族、多租户、平台化运营预留结构

重点事项：

1. 多家族能力
- family 维度隔离
- 多管理员体系
- 家族独立设置

2. 隐私与权限分级
- 字段级权限
- 敏感信息脱敏
- 普通成员仅看授权信息

3. 平台级配置
- 方言称呼包
- 家族模板
- 审批流模板

阶段验收标准：

- 系统具备从单家族向平台扩展的结构基础

## 5. 推荐优先级排序

如果当前资源有限，建议优先做以下 8 项：

1. 疑似重复成员提醒
2. 成员关系冲突校验
3. 快速新增亲属
4. 图谱关系标签与路径高亮优化
5. Excel 导入能力
6. 普通成员补充资料申请
7. 多照片 / 附件支持
8. 成员事件与时间线

## 6. 版本发布建议

### 发布节奏

- 小步快跑，建议按 `双周` 或 `三周` 迭代
- 每次版本只主推 `1~2 个核心主题`

### 每个版本建议包含

- 产品变更说明
- 数据结构变更说明
- 权限变更说明
- 测试重点清单
- 回归验证清单

## 7. 风险与应对

### 7.1 录入成本过高

风险：

- 家族数据多、历史久，管理员手工录入压力大

应对：

- 优先做 Excel 导入和快捷建亲属

### 7.2 数据冲突过多

风险：

- 重名、错绑父母、关系循环、资料矛盾

应对：

- 上线前优先补齐冲突校验与疑似重复识别

### 7.3 图谱复杂度过高

风险：

- 数据量上来后图谱杂乱、难用

应对：

- 采用多视图、分层筛选、路径高亮

### 7.4 权限与隐私问题

风险：

- 家族成员对敏感资料访问边界不清

应对：

- 尽早设计字段级权限与审核流

## 8. 里程碑建议

### M1：可用性达标

- 完成 V1.1
- 支持真实家族数据小规模录入

### M2：录入效率达标

- 完成 V1.2
- 支持批量导入与资料补充协同

### M3：知识沉淀达标

- 完成 V2
- 系统从关系库升级为家族资料库

### M4：平台扩展预留达标

- 完成 V3 核心模型升级

## 9. 推荐下一步执行

建议先按以下顺序立项：

1. 补一轮 V1.1 产品细化 PRD
2. 拆出 Excel 导入、疑似重复、快捷建亲属三个专题
3. 同步输出测试验收标准
4. 再进入开发排期
